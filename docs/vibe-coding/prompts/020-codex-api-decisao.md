## Invariants

1. Every write on an alert locks the alert row first (`linha_do_alerta(..., para_atualizar=True)`),
   so concurrent requests on the same alert are serialized.
2. Once a communication is approved (`comunicacoes.status = 'aprovada'`), the alert is closed:
   any new decision or approval → 409.
3. The analyst is always the authenticated user: `decisoes.analista`, `comunicacoes.aprovado_por`
   and `auditoria.quem` get `usuario.nome`; `auditoria.detalhes.usuario_id` gets `usuario.id`.
4. Every write leaves one `auditoria` row (`entidade='alerta'`, `entidade_id=str(id)`).

## Endpoints

### POST /alertas/{alerta_id}/decisao — body `PedidoDecisao` → `Alerta`
- 404 if the alert does not exist; 409 if it has an approved communication (invariant 2).
- `parecer_id` = newest parecer of the alert (`criado_em DESC, id DESC`) or NULL.
- Insert into `decisoes` (justificativa already trimmed by the schema).
- Set `alertas.status = STATUS_DA_DECISAO[decisao]` and `atualizado_em = now()`.
- If `decisao == "comunicar"`: if the alert already has a communication in `rascunho`, point its
  `decisao_id` to the new decision and keep its text; otherwise insert a new `rascunho` with the
  draft text below. Never two drafts for one alert.
- Audit: `acao='decisao'`, `detalhes = {"decisao", "decisao_id", "usuario_id"}`.
- Return the updated alert through `alerta_de_linha` (status now in front terms, e.g. `"arquivado"`
  → `"arquivado"`, `"aprofundar"` → `"aprofundar"`, `"comunicar"` → `"comunicar"`).

Draft text (`rascunho_comunicacao(...)`, plain PT-BR text, deterministic, no LLM): title
`COMUNICAÇÃO DE OPERAÇÃO SUSPEITA — SIMULAÇÃO ACADÊMICA`, then: account, week (`dd/mm/aaaa a
dd/mm/aaaa`, Monday to Sunday), score in %, predicted typology (`tipologia` or "Indefinida"),
total value and number of transactions, countries, the analyst's justification, the newest
parecer text if there is one, and a closing line saying it is a draft generated by FraudRadar PLD
that must be reviewed before approval. It must stay between 30 and 20000 characters (truncate the
parecer if needed).

### GET /alertas/{alerta_id}/comunicacao → `Comunicacao`
- 404 if the alert does not exist; 404 if it has no communication.
- Newest communication of the alert (`criado_em DESC, id DESC`):
  `alerta_id=str(id)`, `texto=rascunho`, `status`, `atualizado_em = aprovado_em or criado_em`.

### POST /alertas/{alerta_id}/comunicacao/aprovar — body `PedidoAprovacao` → `Comunicacao`
- 404 if the alert does not exist or has no communication.
- 409 if it is already approved; 409 if the alert status is not `comunicado` (the analyst changed
  the decision after the draft was created).
- Update: `rascunho = texto` (trimmed by the schema), `status='aprovada'`,
  `aprovado_por = usuario.nome`, `aprovado_em = now()`.
- Audit: `acao='comunicacao_aprovada'`, `detalhes = {"comunicacao_id", "usuario_id"}`.
